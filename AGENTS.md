## What this is

A test harness for Atlas core, not a product: Atlas Journal exists only to prove that core's shared logic (the `@atlastodo/client-core` package from npm, the `atlas-client` crate and the server) works for an app other than todo. The web app has no releases, no store listings and no native builds; the one thing released here is the `atlas-journal` CLI (`crates/`), which took over core's `atlas journal …` commands. Core — the server, the engine crates and the packages — is [atlastodo/atlas](https://github.com/atlastodo/atlas) (a checkout is expected at `../atlas` by the scripts); the todo app is [atlastodo/atlas-todo](https://github.com/atlastodo/atlas-todo).

- **Core version bumps here are how core changes get exercised by a second app.** After a core release (rc or stable), `deps:update` (weekly, see Dependabot below) moves `@atlastodo/client-core` (exact version, in `apps/journal/package.json` and `packages/journal-core/package.json`) and core's crates (the `tag = "vX.Y.Z"` of `atlas-client`/`atlas-core` in `Cargo.toml`) together, to the same release (the e2e job in `ci.yml` reads the npm pin for its server image); then make the suites pass. A failure is a finding about core: fix it in core (a branch in the core repository), don't work around it here.
- Removed on purpose (2026-10): the Android/iOS builds (native modules, EAS, the Android SDK in devenv, the build-cache workflow, the permission allowlist, store icons and splash, Play upload), the app's release tooling (`version:bump`, release notes, the derived `versionCode`, the web tarball, the JS third-party notices), and the flake (`web-dist`, `nix/bun.nix`, `nix:bun-lock`, the Dependabot bun.nix workflow). Don't bring them back. The JS packages' version stays at `0.1.0`. `release.yml` is the CLI's alone (see CI).

## Dev environment

- All dev commands (`web:dev`, `web:export`, `test:all`, `e2e:cli`, `lint`, `fmt`, `deps:update`) are devenv scripts in `devenv.nix` — run them inside `devenv shell` (or `devenv shell -- <script>`). The root `package.json` has **no** scripts. (The full suite is `test:all`, not `test`, which collides with the shell builtin.)
- Bun is the package manager (`bun.lock` committed; CI installs with `--frozen-lockfile`); Node 26 is the runtime. Bun is pinned to **1.4.2** in devenv (the nixpkgs of `devenv.lock`: `nixos-unstable`, the channel the other atlastodo flakes use) and `.bun-version` (which every `setup-bun` in CI reads with `bun-version-file`), in lockstep: `deps:update` moves both to the Bun that nixpkgs ships. No version pin lives in `.github/`: the weekly refresh pushes with the workflow token, which may not change workflow files.
- Rust: nixpkgs' in devenv (`languages.rust`), `rust-toolchain.toml`'s (an exact version, kept with core's) in CI and the release builds; the MSRV is `Cargo.toml`'s `rust-version`. Core's `atlas-client` and `atlas-core` come by git tag (`Cargo.toml`), never a path.
- TypeScript is 7 (the native compiler) everywhere: the root and both workspaces. Its npm package has no JS compiler API, which is why the linter is oxlint, not ESLint with typescript-eslint.
- A server for development: in the core checkout, `devenv up` and `ATLAS_APPS=todo,journal cargo run -p atlas-server`; `EXPO_PUBLIC_API_URL` defaults to `http://localhost:8080`.

## Verification

- `test:all` = `cargo nextest run --workspace` → vitest in `packages/journal-core` (under Bun: `bunx --bun vitest run`) → jest-expo in `apps/journal` (must run under real Node: `bun run test`).
- `lint` = `cargo fmt --check` + clippy (`--no-deps -D warnings`) + `tsc --noEmit` for both workspaces + `oxlint .` (`.oxlintrc.json`: the typescript-eslint `recommended` rules and react-hooks `rules-of-hooks` (error) and `exhaustive-deps` (warning)) + `prettier --check .` + `scripts/third-party-licenses.mjs --check` (the licences of the packages the web build bundles, against an allow-list mirroring core's).
- `web:export` (or CI's export step) must pass.
- `e2e:cli` (`scripts/e2e-cli.sh`) = a throwaway database, core's `atlas-server` with `ATLAS_APPS=todo,journal`, and the `atlas-journal` CLI: its own end-to-end tests (`crates/atlas-journal-cli/tests/e2e.rs`, `#[ignore]`d without a server, run with `--run-ignored all` and `ATLAS_E2E_SERVER`), then `packages/journal-core/e2e` proves an entry the CLI adds shows up in the app's store and the reverse (edits and trash too), and that an Atlas Todo account gets its journal key on its first journal sign-in. `E2E_WEB=1` also exports the web app, serves it from that server and drives it in headless Chromium (`scripts/e2e-web.mjs`: sign-up, writing, search, a token made in Settings, the CLI both ways, reload). The server is built from `ATLAS_CORE_DIR` (default `../atlas`) or given as `ATLAS_SERVER_BIN`, the CLI built here or given as `ATLAS_CLI`; Postgres from `E2E_DATABASE_URL` (default the devenv one on 5432). CI's `End to end (server + CLI)` job runs the same suites against the pinned core release's image and the CLI built from the commit.

## Layout and rules

- `crates/atlas-journal-rules` — the entry rules in Rust and `JournalClient` (core's `AtlasClient`, a journal session, with the entry operations on top), at parity with `entry.ts`; its tests run on core's `FakeServer` (`atlas_client::testing`). Journal is personal: it registers no app definition, only core's manifest (`manifests/journal.json`, which stays in core: the server reads it).
- `crates/atlas-journal-cli` — the `atlas-journal` binary: the same environment, JSON output and exit codes as core's `atlas` CLI had; commands are flat (`entries list`) or app-first (`journal entries list`, the old form). Its output is pinned by `test-vectors/cli_golden.json` (`tests/golden.rs`; `GOLDEN_UPDATE=1` re-records it, sorting every object's keys: re-record only new scenarios and keep the rest as it was).
- `packages/journal-core` — platform-free: `entry.ts` (the entry fields and rules, at parity with `crates/atlas-journal-rules`; `entry.golden.test.ts` replays `test-vectors/cli_golden.json`, the CLI's golden runs, so a rule change needs both sides to pass), `query.ts`, `entries.ts` (entries in a client-core `LocalStore`), `account.ts` (sign-in/up/unlock, opening the journal app key), `apiTokens.ts`, `engine.ts` (store + `SyncClient`).
- **No crypto here.** Keys and envelopes are client-core's: the password opens the root (`openAccountKeys`, `ensureRootKey` for an account without one), the root opens the journal app key (`enableApp`/`openAppKey`, app `journal`). The journal key plays the DEK's role in the keyring (envelope kid `"dek"`, scope personal). The todo key is never stored. If core lacks something, change core, don't work around it here.
- Every sync request is journal-scoped: build clients with `createJournalApiClient` (`x-atlas-sync-apps: journal`). A journal session has no legacy plaintext: `setLegacyMigrated(true)`.
- `apps/journal` — an Expo Router app for the web only (`platforms: ["web"]`); screens take navigation callbacks as props (the `app/` route files wire them) so tests render them without a router. The session keeps the journal keys only sealed under a non-extractable WebCrypto key (`webKeyStore.ts`); the op log is client-core's IndexedDB persistence, one database per account (`atlas-journal-<user>`), deleted at sign-out; Argon2id is hash-wasm's WebAssembly build.

## CI

- Conventional Commits; a fix closing an issue carries `Fixes #N` in the commit body. Work lands on `dev`; `main` takes only PRs from `dev` (`pr-base.yml`).
- `ci.yml`: `Lint`, `Lint (Rust)`, `Test (Rust)`, `Test (journal-core)`, `Test (app)` (jest + the web export), `End to end (server + CLI)`, `Audit (Rust)` (cargo-deny, `deny.toml`) and `Audit (JS)` (both continue-on-error), chosen by changed paths; a manual run or a release runs everything, the weekly schedule only the audits.
- `release.yml` releases the CLI on a `v*` tag, which must equal `Cargo.toml`'s workspace version (move it by hand, `cargo` updates `Cargo.lock`): `CI`, then `atlas-journal-X.Y.Z-<target>` static binaries (musl on Linux, zig for aarch64; as core's CLI was built), `THIRD_PARTY_NOTICES.txt` of their crates (`scripts/rust-notices.mjs`), provenance attestations and `SHA256SUMS.txt`, in a GitHub Release with generated notes. A tag with `-` (`vX.Y.Z-rc.N`, tagged on `dev`) is a prerelease, never `latest`; a stable one is tagged on `main` after a `dev` → `main` PR. `bun audit` reports only the known unfixable `braces` and `node-forge` advisories; fixable ones go in `overrides`, never an ignore list.
- Nothing is held back on purpose. Dependabot (`.github/dependabot.yml`): weekly version updates for Actions, Bun, Cargo (not core's crates) and the Rust toolchain, grouped minor/patch, targeting `dev`, after a 3-day `cooldown` (security updates never wait). Everything else (`devenv.lock`, the Bun pins, the whole `bun.lock` and `Cargo.lock` with transitives and the `overrides`, the Expo SDK's packages via `expo install --fix`, the core pin and core's crates) is `deps:update` (`scripts/update-deps.sh`), which `deps-refresh.yml` runs weekly and opens as one PR from `chore/deps-refresh`. A new Expo SDK major is a migration, flagged as an issue. `overrides` are ranges, never exact pins.
